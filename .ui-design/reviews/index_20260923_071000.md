# Design Review: Главная страница

**Review ID:** index_20260923_071000
**Reviewed:** 2026-09-23 07:10
**Target:** src/pages/index.astro (+ GallerySection, MapSection, ReviewsSection, ProductCard)
**Focus:** Visual, Usability · responsive, mobile-first

## Summary

All four home blocks sat on one uniform `bg` with only a tiny mono label between them, so the page read as one long undifferentiated sheet. Blocks are now tinted "drawing sheets" (`Section.astro`). Two remaining majors are outside the colour task: no order buttons on product cards, and the reviews block previously broke the no-radius/no-shadow rule (fixed).

**Issues Found:** 7 — Major: 3 · Minor: 3 · Suggestions: 1

## Major Issues

### 1. Blocks visually indistinguishable — FIXED
**Location:** src/pages/index.astro · **Category:** Visual
Every block used the same background and an identical `text-xs` mono divider; only the catalog had a real heading. Fixed with `src/components/Section.astro`: full-width band per block, sheet number `01/04…`, dimension-line rule, `font-display` heading.

| block | band | key colour |
|---|---|---|
| Каталог товаров | `bg` #1B1F22 | `accent` |
| Наша галерея | `band-warm` #221D1A | `sand` |
| Мы на карте | `band-steel` #19232A | `line-strong` |
| Отзывы | `band-moss` #1D221C | `stock` |

`text-muted` stays ≥ 4.5:1 on every band.

### 2. Reviews used `rounded-lg` + `box-shadow` — FIXED
**Location:** src/components/ReviewsSection.astro:40, :124 · **Category:** Visual
Broke the mandatory "no border-radius / no box-shadow" rules. Removed.

### 3. No order buttons on product cards — OPEN
**Location:** src/components/ProductCard.astro · **Category:** Usability
The brief requires Telegram/phone buttons on every card. The whole card is one `<a>`, so buttons can't be nested inside it. Recommendation: make the card an `<article>` with a stretched title link, plus a footer row of `Telegram` / `Позвонить` buttons (as in `.card-actions` in design-a.html).

## Minor Issues

### 4. Heading hierarchy — FIXED
Only the catalog had a heading; other blocks were label-only `<div>`s. Now `<section aria-labelledby>` with h1 (catalog) + h2 per block.

### 5. Placeholder "Категория" shown on every card — OPEN
**Location:** ProductCard.astro:63. It's placeholder data (see CLAUDE.md) and is just noise. Hide it until real categories exist.

### 6. Map traps scrolling on mobile — OPEN
**Location:** MapSection.astro — `scroll=true` in the Yandex constructor URL. On touch devices, swiping over the 400px map zooms the map instead of scrolling the page. Consider `scroll=false`, and a smaller height below `sm`.

## Suggestions

### 7. Inconsistent grid gaps
The catalog uses `gap-px` hairline dividers, while the gallery uses `gap-4` with borders. Consider moving the gallery to the same `gap-px bg-line` grid for a consistent blueprint look.

## Positive Observations
- Tokens are used consistently. No ad-hoc hex values in components.
- Corner tick marks, mono numerics, and hairline borders are applied well on cards.
- Lightboxes support keyboard and swipe input.

## Next Steps
1. Order buttons on product cards (#3) — this is a requirement from the brief.
2. Hide the placeholder category (#5).
3. Stop the map from trapping scroll on mobile (#6).
